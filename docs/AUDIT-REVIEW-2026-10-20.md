## 四、发现（按优先级）

### P1-1 保存的分享图是透明底 PNG，深色模式下不可读

**现象**：`保存图片` 落盘的 PNG 除文字/图形外**全部是 alpha=0**。

**证据**（把设备文件拉到本地逐像素检查）：

| 文件 | 尺寸 | alpha>0 的采样点占比 | (0,0) alpha |
|---|---|---|---|
| `carbonlife-report-1792474857606.png`（自测引用的 144 658 B） | 1126×1445 | 7.43% | 0 |
| `carbonlife-report-1792486166835.png`（本次浅色） | 1126×1372 | 7.55% | 0 |
| `carbonlife-report-1792491609978.png`（本次深色） | 1126×1372 | 7.55% | 0 |

- PNG 头为 colorType 6（RGBA），即带 alpha 通道；
- 浅色导出叠加到白底看还行，**换到深色聊天背景就被吞**；
- 深色模式导出叠加到白底（模拟对方在浅色环境查看）→ 标题「碳账单」「幼苗」几乎看不见、`1.02 kg` 对比度极低：

  > 证据文件：`dark-report-on-white.png`（由导出的深色 PNG 合成到白底）

**根因**：截图节点 `#reportCard` 自身没有背景色，白底来自外层的弹层容器。

- `entry/src/main/ets/view/HomeTab.ets:412-416`：`#reportCard` 的 `Column` 只有 `padding`，无 `backgroundColor`；
- `entry/src/main/ets/view/HomeTab.ets:724`：背景色在父容器 `AppColor.CARD` 上；
- `entry/src/main/ets/view/HomeTab.ets:221`：`componentSnapshot.get('reportCard')` 只抓该节点自身的绘制内容 → 背景透明。

**修复建议**：给 `#reportCard` 显式加背景（并建议加圆角内边距，让导出图自带边距）：

```ts
.id('reportCard')
.backgroundColor(AppColor.CARD)   // 或固定 token，保证深/浅色都是自包含的图
```

如果要"无论 App 主题如何，导出图都统一为浅色卡片"，则在该节点内固定使用浅色 token，或导出前切换到浅色主题。
修完后**必须打开图片本身验收**（含深色模式下导出一张），不要只看文件大小。

### P1-2 「连续 N 天」断签后不归零，长期显示过期连续数

**现象**：最后一次记录在 4 天前，首页仍显示「连续 5 天」。

**复现（本次实测）**：

1. 清空全部数据；
2. 导入 20 条记录，日期为 10-12 ~ 10-16（每天 4 条，全部出行）；
3. 今天 10-20 打开首页 → 卡片显示 **成长值 220 · 小树 · 偏向绿色出行 · 连续 5 天 · 今日 +0**。

预期：连续天数应已中断（显示 0，或「上次连续 5 天」），而不是把 4 天前的连续当成"当前连续"。

**根因**：

- `entry/src/main/ets/model/Sapling.ets:142-166`：`streak` 只在遍历到的记录日内累加，
  循环结束即"当前连续"，**没有和 `todayKey` 做有效性比较**（`todayKey` 只用于 `todayGrowth`）；
- `entry/src/main/ets/view/HomeTab.ets:568-571`：只要 `activeDays > 0` 就渲染「连续 N 天」。

加成计算本身是对的（断签当天再记录时 streak 会重置为 1、不吃加成），**错的只是展示口径**，
但它直接违背「连续」二字的语义，也会让"断签不掉级"看起来像 bug。

**修复建议**：
- `compute()` 里在最后判断：若 `lastActiveTs` 距 `todayKey` 超过 1 天，则 `streak = 0`；
- UI 用 `streak === 0 && activeDays > 0` 时显示「今天还没记录」/「上次连续 N 天」；
- 补一条单测：最后记录日 = `todayKey - 4 天` 时 `streak === 0`。

### P2-1 「每日上限 80」会被连续加成突破

**现象**：卡片显示「今日 +84 · 已达上限」。

**复现**：导入 1 条昨天 + 9 条今天 → 今天 raw 封顶 80，连续 2 天加成 5% → 84。

**根因**：

- `entry/src/main/ets/model/Sapling.ets:144-146`：上限只作用在 `raw`（记录/任务原始值）；
- `entry/src/main/ets/model/Sapling.ets:158-159`：`gained = Math.round(raw * (1 + bonus))` 在封顶之后，
  所以单日最高可达 80 × 1.5 = 120。

于是"上限 80"这句文案在同屏出现时会自相矛盾（+84 且"已达上限"），`docs/AUDIT.md:15,38` 与
`QA_REPORT.md:256` 也都写的是 80。

**修复建议**：把封顶放到最后 `gained = Math.min(Sapling.DAILY_CAP, ...)`；
若确实想保留"连签可超过 80"，则文案改成「原始成长上限 80，连签最高 120/天」，两处口径统一。

### P3-3 碳账单在数据变化时不会实时刷新（需关掉重开）
