## 三、演示种子（可选，快速看到「小树 + 装饰」）

单人单日成长上限 80，干净设备当天看不到阶段 2 的树冠装饰。用种子脚本可稳定复现：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make-demo-seed.ps1 -Days 5 -PerDay 4 -Push
```

1. 脚本生成 `.hvigor/demo-seed-<时间戳>.json` 并推到设备「我的手机」根目录；
2. App：**看板 → 清空全部数据 → 导入数据（CSV/JSON）→ 我的手机 → 选 `demo-seed-<时间戳>.json`**；
3. 若列表里看不到新文件，**返回上一级再进入**刷新一次（系统选择器缓存）；
4. 预期：成长值 **220**、阶段「小树」、偏向「绿色出行」、**连续 5 天**、树冠出现新叶装饰。

> ⚠️ 已知坑：早期脚本用固定文件名 `demo-seed.json`。若设备上残留旧文件，导入后日期会整体早一天，
> 连续天数会显示成「上次连续 N 天」。现已改为**带时间戳的文件名**，请认准最新那个。

## 四、设计要点（可讲）- **成长值完全由记录派生**，没有可写状态 → 无法点按钮刷；
- **每日上限 80（硬上限，连签加成也不能突破）**，约 5~8 条记录封顶；连续记录 +5%/天（封顶 +50%）；
- **断签不掉级**：成长值不回收；连续天数展示会归零（卡片显示「上次连续 N 天」）；
- 阶段阈值 `0 / 60 / 180 / 420 / 900 / 2400`；
- 行为结构决定树冠装饰（出行→新叶 / 餐饮→果实 / 节能→花朵 / 回收→青环），**装饰从阶段 2（180 成长值）起显示**。

### 3.1 演示"新叶"（阶段 ≥ 2）

单日成长最多 80，干净设备当天到不了 180，所以装饰需要种子数据：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make-demo-seed.ps1 -Push
# 输出：20 条（5 天 × 4 条步行，全部"出行"），预期成长 220 / 小树 / 连续 5 天
```

然后在 App 里：`看板 → 本地数据管理 → 导入数据（CSV / JSON）→ 我的手机 → demo-seed.json`。
导入是按 id 合并的，建议先「清空全部数据」再导入；导入后首页应显示「小树 · 偏向绿色出行 · 连续 5 天」，
树冠出现新叶。脚本每次按"相对今天"生成日期，不会过期。
