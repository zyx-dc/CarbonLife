# CarbonLife 演示视频 · 分镜

- 成片：`CarbonLife-演示视频.mp4` — 1920×1080 / **60fps** / H.264 / **35.6 秒** / 9.2 MB / 无旁白
- 工程：`tools/video/remotion/`（Remotion，React + CSS 逐帧渲染）
- 画面：全部是设备真实截图，非重绘件

## 一、三版迭代，两次纠错

| 版本 | 做法 | 结论 |
|---|---|---|
| v1 重绘版（已归档） | 米色背景上重画的界面片段 | 不是 App，撑不住"运行可用"；作废 |
| v2 keynote 慢版（已归档） | 纯黑底 + 手机居中 + 长停留 | 画面是真的，但节奏太慢、闷 |
| **v3 节奏混剪（当前）** | 浅底/暗场交替 + 拍点硬切 + 景别跳变 | 见下 |

**v2 → v3 的两个技术修正：**

1. **抖动**。v2 用 ffmpeg `zoompan` 做缓慢推近，每帧位移不足一个像素，坐标取整后就是肉眼可见的"一格一格"。v3 改用浏览器 CSS transform 做亚像素合成，60fps 下每帧都有连续变化（已用逐帧差分验证：相邻帧差异 1.7–1.9%，无重复帧）。
2. **帧率**。30fps → **60fps**。

## 二、语法（参考产品混剪，不是 keynote）

| 手法 | 具体做法 |
|---|---|
| 拍点 | 120 BPM，一拍 0.5 秒；每条 2–7 拍，硬切不用转场 |
| 景别 | 同一屏连切两级：整机 800 → 860 高，靠"设备变大"制造推近 |
| 明暗 | 亮场特写铺满 / 暗场特写内缩成一块面板，四周留黑——明暗交替本身就是节奏 |
| 排版 | 屏上字只有一行、很小、落在画面下缘 `0.945H`（字幕位）；大字卡才放大 |
| 动效 | 文字卡"上移 20px + 淡入 + 0.985→1 缩放"，缓动只用减速 `cubic-bezier(0.16,1,0.3,1)` |
| 重音 | 全片只有一处青柠色大字：`0.51` |

**素材约束（重要）**：截图只有 1320×2232。任何铺满 1920 宽的裁切都要放大 ≥1.45 倍，正文小字会发虚。所以"特写"一律用**整机在画面里变大**来实现（整机是降采样，怎么都比裁切锐），只有大数字、图表这种图形元素才允许满屏裁切。

## 五、复现

```powershell
# 1) 导入演示种子（见 docs/AUDIT.md §3），按上表在设备上截图到 %TEMP%\demo_assets\
#    命令：devecocli ui screenshot --device "Mate 90 Pro" --path <文件>

# 2) 准备工程素材
cd tools\video\remotion
Copy-Item "$env:TEMP\demo_assets\*.png" public\shots\
Copy-Item "C:\Windows\Fonts\NotoSansSC-VF.ttf" public\fonts\

# 3) 出片
npm install
npx remotion render src/index.ts CarbonLife out/CarbonLife-v2.mp4

# 4) 预览（可拖时间轴）
npx remotion studio src/index.ts
```

改分镜只动 `src/shots.ts`：每条是 `close`（裁切特写）/ `phone`（整机）/ `card`（文字卡），时长为 `beats` × 0.5 秒。

## 六、已知边界

- 截图驱动的演示片，不是连续录屏。原因：模拟器无窗口、系统不提供 `screenrecord`，逐帧截图只有约 3 fps。
- 满屏特写会把画面放大 1.45 倍以上，所以特写只给大数字与图表，正文列表一律用整机。
- 无音乐。若要加节奏更强的音轨，告诉我，我把拍点对齐到选定曲目的 BPM（当前 120）。
