## 一、为什么要重做

上一版（已归档到 `_deprecated-重绘版/`）的画面是**重绘的界面片段**——米色背景中央一张小卡片，只有几个胶囊和一个步进器，不是 App 的真实页面。问题有两个：

1. 演示视频的用途是证明"作品能跑、业务流程完整"，重绘件证明不了；
2. 分镜文档当时写的是"画面来自真机截图"，与实物不符，一问就穿。

新版直接使用设备截图：整屏、真实状态、真实数字。

## 二、风格依据（实测数据，不是二手总结）

参考对苹果产品片的逐帧实测，取的不是"感觉"，是参数：

| 维度 | 实测结论 | 本片做法 |
|---|---|---|
| 背景 | 视频里是纯黑 `#000000`（`#1d1d1f` 是网页值） | 全片纯黑 |
| 构图 | 主体居中（76% 的帧主体落在画面中心 6% 内），大量留白 | 手机居中，四周全空 |
| 字体 | 行高恒等于「字号 + 4px」；字距随字号变（大字收紧、小字放开） | 104px 用 −0.015em，26–30px 用 +0.012em |
| 转场 | 苹果用**硬切**，靠跨切点的连续性藏切点；滑动转场反而是业余感来源 | 全部硬切，手机位置尺寸不变 |
| 节奏 | **双峰**：中位镜头 1.4s，但 11–20s 的长镜头承载 80%+ 屏幕时间 | 9 秒长停 + 6.5 秒三连切 |
| 声音 | 稀疏、只为节点打点 | 静音（片上不放廉价音效） |
| 一镜一意 | 一个镜头只说一件事，揭示前留白 | 数字页前插 1.2 秒黑场 |

唯一的重音色是品牌青柠 `#B6FF2E`，全片只出现在两处：开场的「碳足迹」和 `0.51` 这个数字。

## 五、复现

```powershell
# 1) 先生成演示种子并导入（脚本见 docs/AUDIT.md §3）
powershell -ExecutionPolicy Bypass -File scripts\make-demo-seed.ps1 -Push

# 2) 按上表顺序在设备上截图，存到 %TEMP%\demo_assets\，文件名同「素材来源」
#    截图命令：devecocli ui screenshot --device "Mate 90 Pro" --path <文件>

# 3) 渲染
cd tools\video
python build_film.py --stills   # 只出静帧，检查排版
python build_film.py            # 出全片 out\CarbonLife-演示视频-真机.mp4
```

依赖：Python + Pillow、ffmpeg（libx264）、字体 `NotoSansSC-VF.ttf`（SIL OFL）。

## 六、已知边界

- 本片是**截图驱动的演示片**，不是连续录屏。原因：模拟器无窗口运行、系统不提供 `screenrecord`，逐帧截图只有约 3 fps，拿不到流畅录屏。
- 画面里的数字与当前演示态一致（导入种子后 220 / 0.51 / 421 / 3.91），现场演示可以对照。
- 若要改成"真人实拍+录屏"，需要一台能装本 App 的 HarmonyOS NEXT 设备（当前用户真机为 4.0，装不了本工程）。
