1. 项目概述与选题意义

1.1 项目简介

CarbonLife（碳足迹）是一款运行在 HarmonyOS 手机上的低碳生活记录与激励应用。用户完成步行、骑行、公交出行、节约用电用水、回收纸张 / 塑料 / 金属 / 旧衣、光盘行动等日常低碳行为后，应用按「活动量 × 排放因子」自动估算碳减排量，并折算为碳积分；积分可用于碳普惠权益兑换、解锁低碳徽章与植树证书，还可在同一账号的多设备间共享「家庭碳积分」。

1.2 选题背景

  • 国家「双碳」目标：碳达峰、碳中和已成为国家战略，倡导全民参与绿色低碳生活。
  • 鸿蒙生态：HarmonyOS / OpenHarmony 具备端侧 AI、分布式数据、后台代理提醒等原生能力，适合落地绿色生活场景。
  • 落地价值：把抽象的「碳排放」转化为普通人看得懂、攒得着的「减排量与碳积分」，降低参与门槛，形成正向激励。

1.3 目标用户

关注环保与健康的城市居民、通勤人群与家庭用户；愿意通过日常小行为积累成就感、并希望与家人共同参与低碳生活的群体。

1.4 设计目标

  • 记录简单：3 步内完成一次低碳行为记录。
  • 反馈即时：保存后首页与看板数据实时更新。
  • 隐私优先：数据默认只存本机，不上云。
  • 体验一致：浅色 / 深色双主题，全部走设计 token。

2. 需求分析

2.1 用户痛点

痛点说明
行为与结果割裂用户不知道「步行 1 公里」到底减了多少碳，缺乏正反馈。
记录门槛高很多碳计算工具需要手工查表、换算，操作繁琐。
缺少激励记录本身没有回报，难以长期坚持。
隐私顾虑不愿把个人出行 / 生活数据上传到第三方。
家庭协同缺失希望与家人共同记录，但缺少便捷的多设备共享方式。

2.2 功能需求列表

编号功能说明
F1低碳行为记录出行 / 节能 / 回收 / 餐饮 4 大类共 13 种行为，按排放因子自动计算减排量与积分。
F2端侧 AI 识图选一张照片，端侧识别物体并推荐对应低碳行为。

F5家庭碳积分生成 / 加入家庭码，同账号多设备共享减排量与积分，按成员展示。

F7双碳科普专栏碳达峰 / 碳中和、绿色出行、家庭节能等科普内容与低碳指数自测。
F8浅色 / 深色主题跟随系统 colorMode 自动切换。

2.3 非功能需求

类别要求
性能记录保存与页面切换流畅；图表入场动画受「减弱动效」控制。
隐私记录仅本机存储；AI 识图本机完成；家庭同步不经第三方服务器。
可用性深浅双主题；关键读数清晰；重要操作（删除 / 清空）二次确认。
可维护性颜色 / 字号 / 间距 / 圆角统一走设计 token，禁止硬编码。
国际化界面文案抽取为资源，提供中文 / 英文两套。

3. 系统设计

3.1 技术栈

层次技术
开发语言ArkTS
UI 框架ArkUI 声明式 UI
应用模型Stage 模型（UIAbility）
目标 SDKHarmonyOS / OpenHarmony，compatibleSdkVersion 26.0.0
核心能力@kit.ArkData（Preferences / DistributedDataObject）、@kit.CoreVisionKit（端侧物体检测）、@kit.BackgroundTasksKit（代理提醒）、@kit.MediaLibraryKit / @kit.ImageKit、@kit.CoreFileKit

3.2 总体架构

应用采用「页面 → 组件 → 数据与服务」的分层结构，入口为 UIAbility，主界面为 5 个 Tab。

入口层：EntryAbility（启动配置、深色模式跟随、权限申请）
↓
页面层：Splash 启动页 → Index 主框架（5 个 Tab：首页 / 记录 / 看板 / 积分 / 科普）
↓
组件层：AppCard 卡片 · AppButton 按钮 · Chart 图表（Canvas） · Badge 徽章 · TaskCard 任务卡 · AnimatedNumber 数字滚动
↓
数据与服务层：CarbonStore 数据单例 · CarbonFactors 行为因子 · FamilyService 家庭 · MallService 权益商城 · ReminderService 提醒 · VisionService 识图 · Rewards 积分 / 徽章 / 任务
↓
能力与存储层：Preferences 本机存储 · DistributedDataObject 分布式数据 · CoreVisionKit 端侧 AI · 后台代理提醒

3.3 数据存储设计

  • 本机优先：记录、兑换、任务奖励等存入 Preferences（键值存储），App 冷启动即恢复。
  • 数据同步：UI 通过 AppStorage 的 recordsVersion / familyVersion 与变更监听器感知数据变化并刷新。
  • 家庭数据：基于 DistributedDataObject，以家庭码作为会话标识，在同账号设备间同步成员减排与积分。
  • 导出：支持 CSV（RFC 4180 转义 + UTF-8 BOM）与 JSON，便于备份与迁移。

5. 设计系统与视觉规范

项目以 DESIGN.md 作为设计唯一真相：机器可读的 YAML design tokens 与人类可读的章节说明，颜色 / 字号 / 间距 / 圆角统一引用 token，禁止硬编码。

要素规范
主题「夜行荧光」（深色）与「日光纸感」（浅色）双主题，跟随系统切换。
主色品牌信号青柠 #B6FF2E（深色主题主色 / 信号色）；浅色下关键读数改用可读墨绿。
辅助色青色 #3DE0C8（辅助）、苔绿 #2E8B57、品红 #FF3D9A（极少量点缀）。
圆角 / 间距 / 字号统一走 AppRadius.* / AppSpacing.* / AppTypography.*。
动效统一走 AppMotion，受「减弱动效」开关控制。

7. 创新点与项目难点

7.1 创新点

  • 端侧 AI 识图记录：无需联网，在设备侧完成物体检测并推荐低碳行为，兼顾便捷与隐私。
  • 家庭碳积分跨设备聚合：基于分布式数据对象，在同一账号的多设备间合并家庭减排与积分。
  • 无云本机存储：数据默认仅存本机，配合 CSV / JSON 导出实现手动备份，隐私友好。
  • 可被 AI Agent 消费的设计规范：DESIGN.md 采用 YAML tokens + 章节规范，配合仓库内置的设备验证 Agent，形成可协作、可复现的研发流程。

7.2 项目难点

  • 数据变更驱动 UI 刷新：以 AppStorage 版本号 + 变更监听统一驱动各 Tab 刷新，保证保存 / 删除后首页与看板实时同步。
  • 图表动画与性能：Canvas 手工绘制折线 / 柱状 / 饼图与入场动画，并对稀疏数据改用柱状以避免误导。
  • 深浅主题一致性：硬编码色值审计与 token 化，确保双主题下无残留。
  • 国际化：界面与数据文案抽取为资源并保持中英一致，同时不影响本机存储与导出格式。

8. 测试与验证

项目采用「写审分离」的协作方式：写代码与设备验证由不同 Agent 承担，验证 Agent 只读、不改源码，在模拟器上构建、安装、驱动 UI 并逐条核对验收清单，产出带证据（截图 / dump / 日志）的结论。
