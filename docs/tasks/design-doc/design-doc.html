1. 项目概述与选题意义

1.1 项目简介

CarbonLife（碳足迹）是一款运行在 HarmonyOS 手机上的低碳生活记录与激励应用。用户完成步行、骑行、公交出行、节约用电用水、回收纸张 / 塑料 / 金属 / 旧衣、光盘行动等日常低碳行为后，应用按「活动量 × 排放因子」自动估算碳减排量，并折算为碳积分；积分可用于碳普惠权益兑换、解锁低碳徽章与植树证书，还可在同一账号的多设备间共享「家庭碳积分」。

1.2 选题背景

  • 国家「双碳」目标：碳达峰、碳中和已成为国家战略，倡导全民参与绿色低碳生活。
  • 鸿蒙生态：HarmonyOS / OpenHarmony 具备端侧 AI、分布式数据、后台代理提醒等原生能力，适合落地绿色生活场景。
  • 落地价值：把抽象的「碳排放」转化为普通人看得懂、攒得着的「减排量与碳积分」，降低参与门槛，形成正向激励。

1.3 目标用户

关注环保与健康的城市居民、通勤人群与家庭用户；愿意通过日常小行为积累成就感、并希望与家人共同参与低碳生活的群体。

1.4 设计目标

  • 记录简单：3 步内完成一次低碳行为记录。
  • 反馈即时：保存后首页与看板数据实时更新。
  • 隐私优先：数据默认只存本机；云备份为可选开关，默认关闭。
  • 体验一致：浅色 / 深色双主题，全部走设计 token。

应用采用「页面 → 组件 → 数据与服务」的分层结构，入口为 UIAbility，主界面为 5 个 Tab。

入口层：EntryAbility（启动配置、深色模式跟随、权限申请）
↓
页面层：Splash 启动页 → Index 主框架（5 个 Tab：首页 / 记录 / 看板 / 积分 / 科普）
↓
组件层：AppCard 卡片 · AppButton 按钮 · Chart 图表（Canvas） · Badge 徽章 · TaskCard 任务卡 · AnimatedNumber 数字滚动
↓
数据与服务层：CarbonStore 数据单例 · CarbonFactors 行为因子 · FamilyService 家庭 · MallService 权益商城 · ReminderService 提醒 · VisionService 识图 · BackupService 备份 / 恢复 · Rewards 积分 / 徽章 / 任务
↓
能力与存储层：Preferences 本机存储 · DistributedDataObject 分布式数据 · CoreVisionKit 端侧 AI · 后台代理提醒 · 本地整包快照 / AGC 云存储

3.3 数据存储设计

  • 本机优先：记录、兑换、任务奖励等存入 Preferences（键值存储），App 冷启动即恢复。
  • 数据同步：UI 通过 AppStorage 的 recordsVersion / familyVersion 与变更监听器感知数据变化并刷新。
  • 家庭数据：基于 DistributedDataObject，以家庭码作为会话标识，在同账号设备间同步成员减排与积分。
  • 导入与导出：支持 CSV（RFC 4180 转义 + UTF-8 BOM）与 JSON 的导出与导入；导入时逐字段校验归一化，保证坏数据不污染本机状态。
  • 备份与恢复：本地整包快照（记录 + 兑换 + 任务奖励）导出与去重合并恢复；可选开启 AGC 云存储备份，开关默认关闭，未开启时与纯本地应用行为一致。

5. 设计系统与视觉规范

项目以 DESIGN.md 作为设计唯一真相：机器可读的 YAML design tokens 与人类可读的章节说明，所有 token 与 entry/src/main/ets/common/Theme.ets 一一对应；颜色 / 字号 / 间距 / 圆角统一引用 AppColor.* / AppTypography.* / AppSpacing.* / AppRadius.*，禁止硬编码。

设计语言为「夜行荧光」：深色为默认气质（近黑底 + 电光青柠信号）；浅色为同源 DNA 的「日光纸感」（暖白纸感底 + 墨绿主色 + 青柠轨迹）。两套主题跟随系统 colorMode 切换，冷启动读取系统配置、运行中实时生效，均完整可用。

表 5　设计系统关键规范

要素规范
主题深色「夜行荧光」（近黑底 #0A0A0A）与浅色「日光纸感」（暖白 #F5F7F5）双主题，跟随系统实时切换。
主色 primary深色为电光青柠 #B6FF2E；浅色为墨绿 #16210F —— 青柠在白底不可读，故浅色下 primary 让位墨绿。
信号色 signal青柠 #B6FF2E：与 primary 同值但语义分离，专用于填充 / 描边 / 辉光，其上固定近黑字 #0A0F07。
强调色 accent电青 #3DE0C8（深色）/ #0B7261（浅色），仅用于积分与成就语义。
稀有高光品红 #FF3D9A，仅作极少量点缀（「不和谐的秩序」）。
数据可视化苔绿 #2E8B57 与 chart-* 数据色板；图表主线深色用信号青柠、浅色用品牌绿 #3E8E1E。类别占比与汇总随所选周期联动。
圆角 / 间距 / 字号统一走 AppRadius.* / AppSpacing.* / AppTypography.* 三组 token，禁止硬编码。
动效统一走 AppMotion；进入 / 按压 / 循环动效均读取「减弱动效」开关，开启时退化为静止。

答辩材料说明：投影与打印场景下浅色可读性更好，因此《参赛设计文档》与《答辩 PPT》统一采用浅色「日光纸感」主题（暖白底 + 品牌深绿主色）；为保证远距离投影的可读性，演示材料中的强调色使用暖琥珀色替代 App 界面内的电青强调色。App 本体为深浅双主题完整实现，具体色值以 DESIGN.md 与 Theme.ets 为准。

7. 创新点与项目难点

7.1 创新点

  • 端侧 AI 识图记录：无需联网，在设备侧完成物体检测并推荐低碳行为，兼顾便捷与隐私。
  • 家庭碳积分跨设备聚合：基于分布式数据对象，在同一账号的多设备间合并家庭减排与积分。
  • 本机优先、云备份可控：数据默认仅存本机；备份能力做成「本地整包快照 + 可选云备份开关」，用户不开启时与纯本地应用完全一致，把隐私选择权交回用户。
  • 导入数据的健壮性校验：导入 JSON / CSV / 整包快照时逐字段校验归一化（丢弃无 ID 记录、数值 clamp、单条积分封顶、拒绝异常时间戳），避免坏数据污染本机状态。
  • 可被 AI Agent 消费的设计规范：DESIGN.md 采用 YAML tokens + 章节规范，配合仓库内置的设备验证 Agent，形成可协作、可复现的研发流程。

7.2 项目难点

  • 数据变更驱动 UI 刷新：以 AppStorage 版本号 + 变更监听统一驱动各 Tab 刷新，保证保存 / 删除后首页与看板实时同步。
  • 图表动画与性能：Canvas 手工绘制折线 / 柱状 / 饼图与入场动画，并对稀疏数据改用柱状以避免误导。
  • 深浅主题一致性：硬编码色值审计与 token 化，确保双主题下无残留。
  • 国际化：界面与数据文案抽取为资源并保持中英一致，同时不影响本机存储与导出格式。

8. 测试与验证

项目采用「写审分离」的协作方式：写代码与设备验证由不同 Agent 承担，验证 Agent 只读、不改源码，在模拟器上构建、安装、驱动 UI 并逐条核对验收清单，产出带证据（截图 / dump / 日志）的结论。本节结果为 master 分支上截至 2026 年 10 月 18 日的验证口径。
