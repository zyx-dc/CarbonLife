# 评审会问什么（按"他在探什么"分类）

> 用法：每题先背**一句话答法**（15 秒），再读"他在探什么"理解意图，追问时再展开。
> 配套：`docs/SPEECH.md`（逐字稿 + 技术框架）、`docs/DEFENSE.md`（演示脚本 + 现场 Q&A）。

---

## 一、赛题贴合（最容易问，也最容易丢分）

**Q1 你们做的东西和赛题二的关系是什么？**
一句话：赛题要的三件事我们都在做——**碳足迹记录、碳积分激励、减排指南**；13 种行为是足迹，积分和碳小树是激励，科普专栏和碳账单是指南。
他在探：你有没有跑偏成"健身打卡"或"环保资讯 App"。

**Q2 赛题要求"减排指南"，你们的指南在哪？**
一句话：科普专栏 6 篇 + 每个行为卡上的排放因子 + 碳账单里的减排构成，三处都在告诉用户"做什么最有效"。
他在探：指南是不是只有一堆文章，没有落到具体行动。

**Q3 碳积分和真实碳普惠平台是什么关系？**
一句话：现在是**本地模拟**的兑换码，兑换流程、积分规则、商城结构都是真的，缺的是对接真实平台 API——这一点 PPT 和视频里都写明了。
他在探：你有没有把模拟说成"已落地"。

## 二、技术实现（占比最高）

**Q4 用户记一条行为，系统内部发生了什么？**
一句话：取因子 → 算减排 → 折算积分 → 写本机 preferences → 版本号 +1 → 首页/看板/小树各自重算。
他在探：你是不是只会调 UI，不懂数据流。

**Q5 碳小树的成长值怎么算？会不会被刷？**
一句话：`min(80, 记录数×10 + 任务数×15) × 连签加成`，加成后仍封顶 80；成长值是纯函数算出来的，没有可写字段，前端点不出来。
他在探：核心算法是不是自己设计的。

**Q6 断签掉落吗？为什么这么设计？**
一句话：**不掉级**。断了只把"连续天数"清零，成长值不回收——掉级会制造焦虑，用户断三天就弃用，这是习惯类产品的头号流失点。
他在探：你的产品决策有没有依据，还是拍脑袋。

**Q7 为什么用 distributedDataObject，不用数据库或服务器？**
一句话：家庭场景每个成员只写自己那一行，**不存在同一条数据的并发修改**，所以不需要冲突合并；DDO 是系统提供的同账号多设备同步，零服务器成本。
他在探：技术选型是不是抄的。

**Q8 端侧识图怎么实现的？准不准？**
一句话：`cameraPicker` 或相册选择器拿 URI → 解码成 PixelMap → Core Vision Kit 物体检测 → 标签映射成行为，置信度低于 0.55 直接丢弃；只做**推荐**，用户确认才记账。
他在探：是不是接了个云端大模型糊上去。

**Q9 为什么图片不出本机？**
一句话：链路里根本没有上传代码——选图、解码、推理全在设备侧，网络只用于可选的云备份。
他在探：隐私是不是一句口号。

**Q10 数据存在哪？换手机怎么办？**
一句话：本机 preferences（JSON）；换机走「备份全部数据 → 导出文件 → 新机导入」，云备份是可选开关。
他在探：你有没有考虑数据归属和迁移。

**Q11 导入为什么值得单独做校验？**
一句话：导入是唯一的外部入口，一条坏数据能让列表崩掉；所以做结构校验 + 归一化，CSV 还手写了 RFC 4180 解析（引号内逗号、字段内换行、`""` 转义）。
他在探：边界情况想没想过。

**Q12 单测覆盖了什么？为什么是 21 个而不是 100 个？**
一句话：集中在纯逻辑——成长算法 11 个（封顶、加成、断档、满级）、日期工具、因子查找、导入校验；UI 用冒烟脚本覆盖。
他在探：测试是凑数还是有针对性。

**Q13 你们怎么证明它能跑，而不只是能编译？**
一句话：四道门禁（构建 / lint 0 error / 单测 21 / 冒烟 20）+ 真机逐项验收；验收表里连**没通过**的都单列。
他在探：有没有真实设备验证。

## 三、数据与可信度

**Q14 排放因子哪来的？准吗？**
一句话：公开的低碳行为减排参考值，定位是**量级正确的估算**，不是碳核查；因子表是独立可替换的一层，接真实平台换表即可。
他在探：你会不会把估算说成精确计量。

**Q15 用户随便记，数据不就假了？**
一句话：所以做了三道约束——单日成长上限 80、导入逐字段校验、家庭按成员分别统计；我们不追求"审计级真实"，追求"行为可追溯"。
他在探：你有没有意识到"自证数据"的先天缺陷。**这题答得诚实比答得漂亮重要。**

## 四、AI 使用与原创（红线）

**Q16 AI 在项目里承担了多少？**
一句话：代码提示、文案润色、调试辅助；架构、数据模型、成长算法、同步机制是团队设计并逐条验证的，每个取舍都有单测和验收记录。
他在探：**评审原则第 1 条**——讲不清核心逻辑会被复核，过度依赖 AI 直接取消资格。

**Q17 那你说说这个算法为什么是 80 不是 100？**
（这就是复核）一句话：80 大约等于 5–8 条有效记录，正好覆盖真实的一天；再往上就不是记录，是刷数。
**必须能当场打开 `Sapling.ets` 讲。**

## 五、产品与团队

**Q18 和市面上的碳积分小程序有什么区别？**
一句话：端侧识图降低记录成本、碳小树把减排沉淀成长期可见的成长、数据默认本机 + 家庭聚合。
他在探：有没有想过竞品。

**Q19 你们团队怎么分工的？你负责什么？**
一句话：说清自己那块（架构/算法/前端/测试），并**能指到具体文件**。
他在探：你是不是只是挂名。

**Q20 下一步做什么？**
一句话：接真实碳普惠平台、云备份冲突合并与真机验证、无障碍与平板适配。**不加新玩法，先把这三件做实。**
他在探：有没有清醒的优先级判断。

## 附：三个"必死"回答（千万别说）

| 别说 | 改成 |
|---|---|
| 「这个功能是 AI 写的」 | 「这部分由 AI 辅助实现，我们做了 X/Y/Z 的人工改造与验证」 |
| 「云备份做好了」（其实没通） | 「云备份的桶是开着的，403 卡在签名身份与 AGC 登记不一致，本地备份不受影响」 |
| 「家庭同步没问题」（只有一台设备） | 「本地侧已验证，跨设备合流需要两台同账号设备，我们如实标为待验证」 |
